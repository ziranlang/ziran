# Step 08 — Encode instructions, write objects, and link executables directly

Status: in progress; direct static Linux x86-64 ELFs, PE32+ executables with unwind data, ARMv7/AArch64 static ELFs, a bounded `ar`-archive slice, and in-memory loading of the same encoded image ([README.md](README.md)). Relocatable objects, COFF/Mach-O output and a general native linker remain pending; Apple64 rows are hardware-blocked on a real host and signing facilities. Depends on machine/target contracts from [steps 06](06-optimization-and-native-backend.md) and [07](07-architecture-and-platform-coverage.md).

## Objective

Complete the path from allocated machine instructions to native binaries without generated C, an external assembler, or an external linker on required targets. Keep optional external-tool comparison modes for validation, not as an undeclared dependency of the promised direct build.

## Existing integration points

- [Current C executable driver](../cmd/zi2c/main.c) and [build orchestration](../cmd/compiler_c_backend.zi) provide entry, diagnostics, cache, and failure-preservation behavior to retain.
- [Native entry tests](../tests/native_entry_cases.zi) and [link-flag tests](../tests/native_link_flags_cases.zi) provide existing executable/FFI expectations.
- [Build rules](../Makefile) and [native runtime build selection](../assembly.mk).

Proposed modules: `cmd/compiler_encode_x86.zi`, `cmd/compiler_encode_arm.zi`, `cmd/compiler_encode_aarch64.zi`, `cmd/compiler_object.zi`, `cmd/compiler_elf.zi`, `cmd/compiler_coff.zi`, `cmd/compiler_macho.zi`, `cmd/compiler_link_native.zi`, and `cmd/compiler_disassemble.zi`.

## Implementation work

- [ ] Implement instruction encoding for every emitted opcode and addressing form, including immediate widths, extension prefixes, branch displacement, vector encodings, and target feature validation. Landed slice: the x86-64 encoder covers the emitted opcode/addressing forms with exact-byte fixtures including relocations, fuel and traps ([machine-ir.md](machine-ir.md), [x86_encoder_cases.zi](../tests/x86_encoder_cases.zi)); ARMv7/AArch64 encoders emit their maintained subsets ([machine_elf.sh](../tests/machine_elf.sh)). Vector encodings and full form coverage stay open.
- [ ] Define symbolic fixups independently of object format. Resolve local labels, literal pools, branch relaxation, long-branch veneers, alignment, and padding to a stable final layout. Landed slice: image-relative fixups resolve deterministically for the x86-64 ELF/PE writers, the archive linker, and the in-memory loader ([`compiler_x86_image.zi`](../cmd/compiler_x86_image.zi), [x86_encoder_cases.zi](../tests/x86_encoder_cases.zi)). Literal pools and branch relaxation/veneers for other targets stay open.
- [ ] Print assembly directly from the same allocated/finalized instruction records used by the encoder. Annotate function, source origin, bytes, CPU requirements, stack offsets, and generated instructions. Landed slice: final disassembly reads the actual bytes through the inspection flow with byte maps and identity checks ([vscode-inspection.md](vscode-inspection.md), `zx2native --emit map` in [machine_elf.sh](../tests/machine_elf.sh)); an internal printer annotated from encoder records remains open.
- [ ] Provide a reader for the emitted textual listing that reconstructs its supported instruction/directive subset. Deliberate post-cutover extension per the [milestones](milestones.md) review (“unbounded extras”): listings are inspection views of encoder records, not a required assembler dialect, and no round-trip reader is planned before cutover.
- [ ] Keep existing user `#asm` syntax support a separate compatibility task: parse and bind the supported templates and constraints, including labels/directives where allowed. On the direct assembly target, require a matching declared target/feature implementation and issue a stable diagnostic when absent; do not execute the portable body or invoke another backend.
- [ ] Write relocatable ELF, COFF, and Mach-O objects for required rows. Include text/data/readonly/BSS/TLS sections, symbols, visibility, alignment, relocations, unwind records, and debug references. Landed slice: static ELF executables with text/rodata/data/BSS, symbols and `.eh_frame` ([`compiler_machine_elf.zi`](../cmd/compiler_machine_elf.zi), [machine_elf.sh](../tests/machine_elf.sh)) and PE32+ with base relocations and x64 unwind data ([`compiler_machine_pe.zi`](../cmd/compiler_machine_pe.zi)) exist, plus ARMv7/AArch64 static ELFs. Relocatable objects, COFF, Mach-O and TLS sections remain open; Mach-O is hardware-blocked on a real Apple host and signing facilities.
- [ ] Implement archive reading and symbol extraction, COMDAT/coalescing rules where required, weak symbols, unresolved references, duplicate definitions, section garbage collection, and retained exports/callback roots. Landed slice: a `NAME.library` registration may name an `ar(1)` archive of ELF64 x86-64 objects ([`compiler_x86_archive.zi`](../cmd/compiler_x86_archive.zi)); the reached members' text, read-only data, writable data, zero fill, GOT entries and relocations go into the static Linux ELF and each capability's veneer calls its member directly. Anything outside that subset (TLS, `init_array`, an undefined or duplicate symbol, an unsupported relocation) is the stable `assembly.gap.machine-archive` diagnostic naming the capability, the member and the symbol.
- [ ] Link supported executable/shared-object forms: ELF program headers and dynamic records, PE imports/exports and relocation tables, and Mach-O load commands/fixups as required by the maintained targets. Landed slice: static ELF executables with RX/R program pages, PT_INTERP/PT_DYNAMIC host-library linking and GOT/data relocations, and PE32+ IAT imports, DYNAMIC_BASE/HIGH_ENTROPY_VA/NX and base relocations ([step 07](07-architecture-and-platform-coverage.md) registry notes, [native_entry.sh](../tests/native_entry_cases.zi)). Shared-object ELF output and Mach-O load commands stay open.
- [ ] Implement startup/entry handling and runtime helper linkage for console programs and libraries. Preserve command arguments, exit status, global initialization, thread/runtime setup, and foreign callbacks.
- [ ] Resolve ordinary OS and third-party libraries through explicit target search paths and format-aware symbol handling. Existing compiled foreign libraries are valid inputs; compiling their C sources is outside Ziran code generation.
- [ ] Inventory C-compiler-driver conveniences previously supplied by `CC`: CRT selection, sysroot, libc, dynamic loader, TLS, compiler support routines, and default libraries. Replace each with explicit native driver configuration and diagnostics.
- [ ] Define the supported native link-option surface. Preserve C-target pass-through options on the C backend; reject options that have no new-native equivalent instead of ignoring them.
- [ ] Implement platform-required executable authentication/signing integration where needed for a runnable artifact. Use installed OS signing facilities and explicit credentials; do not claim that a written Mach-O/PE file alone proves launchability. Hardware-blocked today: no Apple host or signing facilities are available, so Mach-O/Apple64 rows stay Unknown (Windows PE launch on real hardware is likewise unproven; Wine is emulation, never row evidence).
- [ ] Write outputs atomically, preserving the last valid executable on failure. Cache object contributions using target, ABI, backend, flags, dependencies, and runtime identities. Landed slice: format tools write a sibling temporary and replace the target only after a complete write ([zx-executable-format.md](zx-executable-format.md), [machine_ir_cases.zi](../tests/machine_ir_cases.zi) failure-preservation fixtures), and the bundle native cache is keyed by bundle/libraries/CPU/compiler identities ([native_cache.sh](../tests/native_cache.sh)). Per-object contribution caching beyond the bundle cache stays open.
- [ ] Produce relocation/link maps, section sizes, resolved symbol addresses, inserted stubs, padding, and a source-linked disassembly from actual final bytes. Landed slice: `zx2native --emit map` publishes a bounded byte map with sections, symbols and resolved extents ([`zx2native.zi`](../cmd/zx2native.zi), [machine_elf.sh](../tests/machine_elf.sh)), and the inspection flow disassembles the final ELF against that map ([vscode-inspection.md](vscode-inspection.md)). Stub/padding attribution and inline-frame mapping remain open.
- [x] Expose the same encoder and relocation primitives to the in-memory loader in step 09; do not create an unrelated JIT instruction encoder. ([`zir_host_native.c`](../bootstrap/runtime/zir_host_native.c) compiles verified ZX with the same machine pipeline, resolves the image's relocations against instance data/veneers/trap stub, and only then flips pages to RX; [native_load.sh](../tests/native_load.sh) retains it.)

## Tests

Add Ziran encoding/object/linker test programs. Compare individual instruction bytes against an independent assembler/disassembler; test boundary immediates, all register forms, branch expansion, relocation overflow, and malformed input objects.

Round-trip the supported listing form through parsing/encoding and compare resulting sections and fixups. Link new-native objects with independently compiled C callers/callees and, where useful, the system linker as a reference. Then run the fully internal link path with external C compiler, assembler, and linker commands unavailable.

Exercise executable launch, dynamic imports, TLS, callbacks, shared libraries, debug/unwind loading, missing symbols, archive ordering, failed writes, and preservation of installed outputs on each required OS. Run all builds through `build-queue --`; use private display fixtures where needed.

## Exit gate

Required standalone builds produce runnable binaries using the internal code generator, encoder, object writer, and linker. Listings match the encoded instruction stream; final disassembly accounts for linker-added code. No external-tool or alternate-engine fallback exists on the direct path; a missing internal facility is a visible Gap.

## Handoff

Deliver encoded-image APIs, relocations, link maps, independent byte/ABI fixtures, platform signing requirements, and final byte-to-source mappings to steps 09–10.
