# Code-size reduction plan

Analysis and implementation ledger, 2026-11-17. Answer to the owner question, verbatim:
"how many lines of code is ziran and how can reduce it by 20%". This file
tracks source cuts. Owner rules honored: "remove" means delete; only unreached
or unneeded code is cut; no file merges for show; manual safety by default; one
bundle format (already one); any new code named here is clean modular Ziran.

## What counts and how it was measured

The owner fixes the denominator at **290,000 hand-written text lines** from
`origin/master` at `51544998`; the required net cut is **58,000 lines**.
The inventory below is a planner's working-tree snapshot including concurrent
edits, not a replacement baseline. Binaries, generated receipts and finished
plans do not count toward the hand-written reduction. The owner's baseline
lists `include/` (35,922 lines of it `ziran_simd_ops.h`) among the hand-written
lines, so deleting committed SIMD headers counts; the Ziran code that replaces
them is subtracted, and the generated seed it adds under `bootstrap/` is
reported beside the cut, as the other seeds are.

Cut 1 deletes `ExternKindName` (11 lines), which has no declaration,
caller or documented external interface, and `loop_leaves_early` (37 lines),
an uncalled static emitter function. It deletes two completed plans and removes
their obsolete cross-links from two open plans. It also deletes the benchmark
owner's superseded `wasm-tier-go-2026-11-16.json` and three explicitly stale
public kernel-target receipt copies. All live benchmark inputs and retained
evidence listed by the benchmark owner remain.

Exact local gate command (2026-11-17, successful):

```text
env -u DISPLAY -u WAYLAND_DISPLAY -u XAUTHORITY -u DBUS_SESSION_BUS_ADDRESS build-queue -- make check &&
env -u DISPLAY -u WAYLAND_DISPLAY -u XAUTHORITY -u DBUS_SESSION_BUS_ADDRESS build-queue -- make check-bootstrap
```

The full suite executed all 284 checks (0 reused) in 229.5 seconds. The bootstrap
gate compared every listed Linux seed module and the three Darwin platform
modules. This small dead-function cut does not change an external interface;
Kryon push-check is reserved for the larger runtime/build removals.

Cut 2 removes `bench/results/history/`, an archive of old revisions, profiles
and failed baselines. An audit of maintained source, generators, tests,
documentation and open plans found no references to 90 unique filenames.
The remaining 11 filenames were generic (`README.md`, `metadata.json`,
`samples.jsonl`, `summary.json`, `results.json`, `migration.json`): explicit
searches for the historical directory and cohort names found no maintained
references either. Every removed path was unchanged against `origin/master`
before deletion. Live standard and kernel receipts and all published matrices
remain. The benchmark owner was given the manifest; no current generator
includes this archive in its enumerated live inputs.

Cut 3 replaces `scripts/simd_header.py` (3,081 lines) with a Ziran
generator, `scripts/simd/` (17 modules, 2,563 lines), and deletes its committed
outputs: `include/ziran_simd_ops.h` (35,922), `include/ziran_simd_types.h` (94)
and `cmd/zir/zir_simd_go_bodies.h` (2,241). The build compiles the generator
from its seed in `bootstrap/simd/` with the host compiler and writes the three
headers into `$(BUILD_DIR)/simd/` before anything includes or embeds them; the
bootstrap compiler reuses them. Its output is byte-identical to the deleted
files except for the first comment line, which now names the generator: all
1,064 C helper bodies, the common section, prototypes, tier macros, the
native-vector section, the types header and the Go tables. `check-bootstrap`
regenerates the seed from `scripts/simd/` and compares it; `update-bootstrap`
refreshes it. One seed serves Linux and Darwin (their generated C is
identical). `tests/simd_go.sh` drops its three Python comparisons, which the
seed check replaces. Net: 41,352 hand-written lines removed, 2,601 added
(generator, Makefile rules, test and comment lines).

Generated-data removal so far totals **81,949 text lines**, with compressed
data counted only in bytes. It contributes **zero** to the 58,000-line code
target.

Implementation corrections to the planner's candidates:

- `PrintLir` is **live**: `#program_export "AssemblyPrintLir"` exposes it to

## Bootstrapping order (scope change, 2026-11-17)

Owner, verbatim: "okay but f ocus on bootstarppning more code please". The
work is now to move each live C pipeline stage into self-hosted Ziran that the
bootstrap builds (a seed under `bootstrap/`, checked by `check-bootstrap`),
prove identical output, then delete the C stage and anything only it used.
`plans/2026-11-14-self-hosting.md` keeps the full file-by-file map (S1, ZIR to
LIR, and S9, C build/cache, are done). A port moves lines rather than
removing them: S1 replaced 5,421 C lines with 7,854 Ziran lines. A stage
therefore counts toward the line target only by what its port reuses, and
its net is recorded in the ledger when it lands.

## Ranked cuts

### 1. Retire the hand-written compiler C (−88,497 lines, 28.4%) — redesign, already planned

Files: `cmd/zir/` (65,471 `.c` + 5,612 `.h`), `cmd/zi2c` (4,380 + 118),
`cmd/zi2go` (4,280 + 51), `cmd/zi2zx` (748 + 50), `cmd/zx2wasm` (5,420 + 134),
`cmd/zx2native` (1,049), `cmd/zi2zir` (244), `cmd/zir-api` (604),
`cmd/zir-inspect` (336).

Evidence that this is live code, not dead: `nm` shows every tool binary
(zi2c, zi2go, zi2zx, zx2wasm, zx2native, zi-edit, zi-api, zi-inspect, zi2zir,
each ~3.6 MB) links the C front end plus the translated `.zi` front-end
modules; `bin/ziran` (504 KB) is the Ziran package driver that spawns them;
`assembly.mk` translates `cmd/compiler_*.zi` into `BUILD_DIR` C at build time
and links `assembly-core.o`/`native-core.o` into the final tools. Nothing here
can simply be deleted today; it is replaced, not disabled.

The replacement vehicle already exists and is owner-approved:
`plans/2026-11-14-self-hosting.md` (owner, verbatim: "and wyh arenty ou
writing al of ziran in ziran so we can bootstarp it"). It maps every C file to
a Ziran destination and deletes each C file in the step that ports it, gated on
byte-identical generated output, then `make check-bootstrap` (Makefile:772)
and a full `make check`. Risk: high effort, staged so every step is provable;
the C lowerers (`zir_c_lower.c`, `zir_go_lower.c`, `zx_wasm_lower.c`) and the
PARSE/CHECK/EMIT parts are live in every gate, so they go last, per file.
Owning area: compiler. This single tracked plan exceeds the 20% target.

### 2. Absorb the `.sh` harness into the Ziran check runner (−1,900 now; −4,000 to −6,000 staged) — mechanical then redesign

Files: `tests/*.sh` (27,972 lines, 265 scripts) vs the existing Ziran runner
`tests/check_plan.zi` (203) and `tests/check_support.zi` (77).

Measured duplication: 211 scripts repeat `repo=$(CDPATH= ...)`, 194 repeat the
`mktemp`+`trap` cleanup, 128+108 repeat the `ziran=$1` argument plumbing, 265
repeat `set -eu`; the runner can create the work dir, own the trap and pass
paths, deleting 6-7 header lines per script (~1,400) plus shared idioms
(78 occurrences of the `cmp source saved` block and its loop, ~500).
Gross duplication ceiling measured across all scripts: 11,888 line occurrences
appear 3+ times (4,049 substantive). A staged port of driver logic into case
modules (Ziran, per owner rules) reaches the larger estimate; the fixture
programs move with it, so savings are net of re-grown `.zi` lines.

Risk: mechanical for the header absorption; the port needs per-script
`CHECK_FILTER` comparison against pre-port logs, then full `make check`. Tests:
`make check` with `CHECK_FILTER=<script>` per step. Owning area: tests.

### 3. Delete unreached `.zi` definitions (−834 lines, level 1) — mechanical, low-medium risk

Files: 35 definitions across `cmd/compiler_*.zi`. Largest:
`PrintLir` (`compiler_zir_lower.zi:7732`, 255), `EmitRuntimeHeaders`
(`compiler_runtime_emit.zi:90`, 78), `CompileExecutable`
(`compiler_backend_process.zi:255`, 44), `MachinePeLibraryDefines`
(`compiler_machine_pe.zi:438`, 42), `MachineElfLibraryDefines`
(`compiler_machine_elf.zi:379`, 41), `NativeCacheDecodeChecked`
(`compiler_native_cache.zi:195`, 35).

Preliminary evidence, requiring export-aware verification: identifier-frequency sweep over the full corpus (all `cmd`, `std`,
`tests` incl. `tests/spec/`, `scripts`, `examples`, `web`, `Makefile`,
`assembly.mk`) plus `nm` over every built binary and `libziran.a`: each name
occurs only at its definition; spot checks against the generated `build/`
trees show no generated callers either. This also explains the 306 dead global
symbols in the shipped binaries (mirrored dead C from `--no-main` emission).
The full list is saved during analysis; each deletion is verified with a
fresh caller search before removal, and deletion can orphan further level-2
callees, so repeat until fixed-point.

Tooling note: a `zi2c --report-unreached` flag (new code in Ziran, in
`cmd/zi2c`) would make level-2 closure a routine check instead of a sweep.
Tests: full `make check`, plus `tests/spec/` for touched modules. Owning area:
compiler modules.

### 4. Dead C functions (−650, informational, subsumed by item 1)

Measured: 306 global symbols defined but unreferenced by any binary, object or
source; 66 have definitions in hand-written `cmd/*.c` totalling 807 lines, of
which ~100 lines are exercised by tests (`GoSimdWriteCheck`,
`ExecBundleCapability*TypeId`, `TokenKindName`, overlay tests) and stay until
their tests change. The rest die automatically when item 1 deletes their files;
if self-hosting stalls, they can be removed first, per symbol, with
`tests/compiler_*_test.c` and `make check` as the gate. No separate action
needed. Owning area: compiler.

## Candidates investigated and rejected (evidence)

- **C front end "duplicated" in Ziran**: both parse/check/emit stacks are live
  for different binaries (see cut 1 evidence). Not dead code; replaced only via
  the self-hosting plan. Confirmed with the coordinator.
- **Bundle component/state/asset API**: unreferenced inside this repo, but
  consumed by `waozixyz/apps/breeze/tests/` (radio_app_test.c,
  apps_host_test.c, bundled_runtime_host.c) and
  `waozixyz/games/shovey/tests/secret_results_host.c`. Live; keep, including
  `std/bundle_host.zi` (451) and `tests/bundle_component_test.c` (286).
- **Orphaned test case modules**: none. `tests/packages_cases.zi` composes
  `package_*_cases.zi` stems at runtime (`CheckConcat(name, "_cases.zi")`,
  check_plan.zi:95); encoder cases are imported by
  `tests/machine_encoder_build.zi`. Tests are tight: only 10 level-1 unreached
  defs in `tests/*.zi`, several of them linker `__wrap_*` symbols.
- **`std/*.zi` unreached procedures**: 191 level-1 defs, but std is shipped
  user-facing API; cutting it loses behavior for programs outside this repo.
  Excluded under "no lost behavior".
- **Legacy formats and shims**: the remaining "legacy" hits are behavior, not
  dead paths (bundle Legacy-version rejection in `compiler_bundle.zi:359`,
  legacy asm mnemonic spellings in `zir_asm.c:554`, rejected `f64` spelling in
  `package_features.zi:182`). Removed engine/tool names (zi2py, zi2zib,
  zi2cpp, zi2rust, zi2zx-vm, zi2wasm, zi2asm) are already deleted from source;
  `make all` only cleans stale binaries (Makefile:300).
