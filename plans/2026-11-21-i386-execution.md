# i386 ZX execution for emu

The current target is a 100× improvement in Rill-class workloads on the
32-bit TaijiOS emulator. The installed changes and their measured results
are documented below and in the [runtime report](../bench/results/rill-runtime-2026-11-21.md).

## Withdrawn interpreter candidate

The first trial of scalar copies, narrow division and adjacent dispatch was
withdrawn before installation. Only its optimization hunks were reversed.
The retained parity tests and raw measurements remain available.

That candidate resolved a copy's backing address and value location
once, specializes 1/2/4/8-byte scalar loads and stores, and copies disjoint
aggregates eight bytes at a time. Frame copies retain their forward byte-copy
semantics when ranges overlap. Byte assembly remains little-endian and allows
unaligned addresses. Pointer generations, extents, read-only checks, canonical
scalar masks and work charges remain in place.

Integer division and remainder use native 32-bit arithmetic for guest widths
up to 32 bits. The signed minimum divided by minus one retains its defined
wrapped result, and zero divisors retain the same failure. Tests cover these
boundaries, negative quotients/remainders and unsigned upper-range operands.

Compact and packed execution can dispatch an adjacent address derivation and
its load/store together. Both instructions still execute and produce their
normal values. The second instruction pays its own work after advancing the
position, so low-budget and pointer failures retain their instruction. This
uses no additional plan storage or address-lifetime assumptions. Edge metadata
is fetched only for a jump or branch.

The retained `lowered_exec` test now compares full-plan, compact and reference
results across sampled work/fuel budgets. Explicit scalar-memory cases cover
signed/unsigned 8/16/32/64-bit values and float32/float64 at a field offset of
one byte. Existing pointer, read-only, heap-generation and aggregate cases
also take the compact parity route.

## Native i386 path

The architecture enum and native loader currently support x86-64, AArch64,
ARMv7 and the separate Wasm tier. An i386 implementation requires:

1. Add an explicit target and Linux System V i386 ABI. Define register-pair
   rules for 64-bit integers, stack arguments, aggregate returns, stack
   alignment, callee-saved registers and floating-point values. ARMv7 provides
   the closest existing 32-bit ABI and checked-pointer template; x86-64
   provides instruction encoding patterns.
2. Extend machine lowering and register allocation for paired integer values,
   legal byte-register operands, fixed-register multiply/divide and spills.
   Add Ziran tests for carry/borrow, shifts crossing 32 bits, signed division
   edge cases and constrained-register pressure before generating code.
3. Implement 32-bit x86 encoding and relocation. Test ModR/M, SIB,
   displacement boundaries, low-byte registers, relative branches and
   stack addressing against a system assembler.
4. Implement the native loader, executable-memory protection transitions,
   checked-pointer arena integration, frame/heap/fuel veneers and typed host
   callback ABI. Keep the host's 32-bit address-space and memory limits.
5. Define explicit function-level eligibility and interpreter transfer
   boundaries if mixed execution is adopted. An unsupported operation must
   never silently restart a partly executed function or lose globals, heap,
   host effects, work, fuel or a precise failure position. Current native
   execution does not implement such fallback.
6. Enable explicit native selection in Taiji's ZX hookup only after typed
   host calls and reentrant module calls pass parity. Do not change its
   engine policy merely by broadening an architecture preprocessor guard.
7. Measure unchanged Rill bundles and the row kernel on physical Alpha.
   Retain raw samples, apply the same outlier rule to C and ZX, and measure
   private-Xvfb first-frame and idle CPU separately. A speedup in a row
   microbenchmark cannot stand in for startup or total frame time.

This crosses target selection, ABI, machine lowering, allocation, encoding,
loading and the Taiji host boundary. It is substantially larger than the
bounded interpreter patch. A bounded per-function fast-code cache could be
evaluated before the native backend, but must not restore the large
whole-program plan that compact execution deliberately avoids.

## Borrowed scalar slices

The separate packed-pixel presenter exposed the cost of expanding a read-only
`[]u32` strip into thousands of `HostValue` elements, then re-encoding and
comparing the unchanged elements. The engine now supports an explicit
`BundleInstanceBorrowHostSlice` or `ZxModuleProgramBorrowHostSlice` opt-in
after instance initialization. A qualifying `#reads` callback receives one
`HOST_BORROWED_SLICE` with the element count and packed little-endian bytes
for a top-level fixed-width integer or floating-point slice.

The borrowed path checks the same address generation, extent and element
type, and accounts for the same logical byte limit and input work charge.
The final candidate also checks that the interface spells the exact built-in
scalar type the verified LIR contains.
The data can be unaligned. The callback reads the bytes synchronously and
does not retain them. Same-instance reentry is rejected while the engine
is running. The ordinary mutable `HOST_SLICE` path is still available, and
native and Wasm reject the opt-in. No engine limits or bundle format changed.

## Linux/i386 hot scalar blocks

The compact engine now has an optional run-loop hook for hot block entries and
scheduled points within a block. On Linux/i386 the hook compiles contiguous
runs of verified 8-, 16- and 32-bit scalar arithmetic into native code and
operates on the current frame's canonical scalar words. The interpreter runs
memory operations, calls and block exits, including the instruction at which a
native check stops. The compiled run is entered only when its full fuel and
work charges fit. A checked division or shift returns the completed prefix so
the interpreter can report the original failure location.

Each instance has a fixed 16-entry cache, a four-visit threshold, and at most
64 compilation attempts. Each trace scans at most 128 instructions and emits
at most 64 instructions into one 4 KiB page. Pages switch from writable to
executable and are released on replacement and instance close. Hosts without
compatible executable mappings continue with the same packed interpreter.
The bytecode, public ABI, and engine allocation limits are unchanged.

The initial prefix implementation compiled in the retained Linux/i386 host
configuration and passed hosted parity, including identical divide-by-zero,
invalid-shift and bounds failure locations. The current implementation can
also schedule a run following an interpreted load or other instruction. The
hosted regression fixture exercises both packed and ordinary readers, native
execution where available, host effects and instruction limits. Its optional
Linux/i386 check confirms executable anonymous mappings exist during the hot
run and are reclaimed at close. The selected release archive stays unchanged
pending the final parity, matched physical Alpha timings, and integration.
