This page reports the local repository as it exists now. Architecture, .zir, and .zx define the target state.

Test citations below include historical verification. The lean-suite pruning removed redundant scripts; those fixtures remain in Git history. Run make check for the complete current suite.

Working now

  • Native C programs can import portable standard facades for common platform services. std/thread selects pthreads or native Windows threads while preserving one Thread API; std/byte_text, std/environment, std/timer, std/random, std/mapped_file, std/stdio, std/parallel and std/file_tree similarly hide native-backend modules.

  • std/simd vector types and operations run with identical bits in native C (GCC and Clang vectors with SSE2, SSSE3, SSE4.1, AVX2 and NEON intrinsics, or the lane loops TinyCC and other compilers use), Go lane loops, bundles on the native engine and the portable VM, from source and saved IR. #target procedures get SSSE3, SSE4.1 and AVX2 clones in C behind a dispatcher that reads CPUID (and the OS's YMM state) once; ZIRAN_SIMD_TIER forces a lower tier, and tests/simd_target.sh checks each forced clone under gdb where it can. Checking rejects 256-bit vectors by value at a #target procedure's boundary and in its calls. C built for wasm32 with -msimd128 uses SIMD128 instructions and gives the same lanes under wasmtime as a build without them; bundles on a WebAssembly host run SIMD through the portable VM. ARMv7 builds with NEON, with VFP only and with scalar lanes give the same results on an ARMv7 phone; AArch64 builds hold NEON instructions but run only under a QEMU_AARCH64 here.

  • GCC object-cache preparation pipes the empty compile probe, allowing its compiler and assembler to overlap without a temporary assembly file. It keeps the previous compiler, math-library, assembler and checksum information and fingerprints the complete derived command options, including installed specs changes. Clang retains its ordinary single compile probe. Failed, incomplete, ambiguous or oversized probe output falls back to normal compilation. tests/native_build_cache.sh covers changed compiler configuration and library versions, both probe paths and failure fallback; process profiles count the probe operations. Runtime-include scanning keeps literal token lengths in its table rather than computing them for every emitted identifier. A successful piped identity probe also enables piped object compilation, overlapping compiler and assembler stages for each generated translation unit. Existing explicit flags are retained without adding a duplicate object-compile flag; unsupported or failed probes keep ordinary compilation. Cache identities include this compile policy, and profiles count piped object attempts. The native-cache test observes actual native-driver arguments, unchanged-object reuse, explicit flags and failed-probe fallback. Linker selection/pass-through flags (-fuse-ld=, -Wl,, -Xlinker) and tool prefixes (-B) also retain object reuse. The probe fingerprints the selected compiler/assembler and include roots; changed prefix tools invalidate their objects. Linking runs on every build, regenerates requested maps and checks current library inputs. Source/saved-IR tests cover these options, prefix-tool replacement, option values and missing-library failure. The identity hashes only environment variables a compiler reads, so another shell or build-queue ticket reuses objects, and accepts a #! compiler wrapper by its content. Adding a generated C file (a split unit or a new module) rebuilds only that file. tests/native_object_reuse.sh checks a one-module edit rebuilds one object across these cases.

  • Generated C public headers carry lightweight string value and caller location definitions. Sources include string operations, bounds checks and standard-library helpers when their emitted code uses them, reducing the preprocessing needed by numeric modules. Runtime headers bring their own dependencies into the output directory, so generated code remains directly buildable without Ziran's include directory. Native string representation, embedded NUL bytes, checked bounds and float formatting remain the same. tests/native_runtime_headers.sh checks source and saved IR, exported ABI values, standalone C builds and stable copied-header timestamps.

  • C emission collects a module in a memory stream where supported (a temporary stream elsewhere) and resolves runtime includes and numeric helpers while writing its final temporary output. Memory streams avoid writing and rereading an intermediate C file. Identical generated files keep their timestamps; large source and saved-IR modules are executed by tests/native_runtime_headers.sh.

  • Native C compilation uses up to sixteen available CPU workers, bounded by the source count and by the process's CPU affinity on Linux. It refills each slot independently, including when another file is slow. Linux child-completion descriptors avoid periodic wakeups when available; other systems retain an owned-PID wait path. JSON compiler logs remain in source order, failed builds drain started jobs and retain the existing executable, and unrelated children remain waitable by their caller. tests/native_build_parallel.sh checks both output modes, blocked workers, truncation, failure and fallback; the native object-cache tests cover incremental reuse and changed inputs. Profiles separate native toolchain preparation, objects and linking and count compilation attempts and reuse. bench/native_builds.py can pair a preserved compiler with the current one alongside C and Go. Tool probes, compiler workers and the linker prefer posix_spawnp, with fork/exec retained when spawning fails. Capture pipes, inherited build locks and owned-child waits keep the same behavior. The parallel-build checks also cover missing tools, executable scripts without a shebang, forced spawn unavailability and child-held locks after their builder exits. Profiles count spawn and fork launches separately; gains depend on the host and workload. Android hosts below API 28 keep fork/exec without references to unavailable spawn symbols; optional NDK checks link both paths for all four Android ABIs. Tool identities are sorted separately from ordered include roots, so moving the assembler's verbose command across the compiler's search diagnostics does not invalidate otherwise reusable objects. The cache checks reproduce both output schedules with the same options and include-root precedence. When a complete GNU assembler/BFD version banner splits cc1's compiler prefix from its GMP library versions, the fingerprint reconstructs those two records without dropping their contents. Checks cover the actual unchanged-build path, changed versions and ordered options, CRLF and incomplete or unfamiliar records; unrecognized interleaving remains a conservative miss. Profiles separate cache lookup and recording from the overall object stage. Dependency-name lists retain insertion order, grow geometrically and index exact duplicates once a list reaches 32 items. Sorting or canonicalizing names discards that index. The cache retains its existing content hashes, search-order validation and metadata format; hash buckets use equivalent 32-bit arithmetic to avoid wide multiplies on 32-bit compiler hosts.

  • Qualified field types traverse reachable imports with an indexed visited set and an explicit, growing depth-first stack. The former 512-module cutoff is removed, while the caller's type visibility checks and symbol generation invalidation remain in place. Checks cover 2,049-module wide graphs, a 4,096-module cycle on a 256 KiB thread stack, and first/last fields in a 554-module program from source, saved IR and bundles. Native foreign layout checks retain the full 2,048-byte record ABI.

  • Public type re-exports use an iterative graph walk instead of a bounded recursive search. Entry-local types keep file/module shadowing precedence; transitive lookup follows public using edges and stops at module locals. Private imports remain usable locally without exporting their type names. Conflicting declarations remain ambiguous even when another route supplies one of them. Checks cover source/saved cyclic 64-module chains, native and portable execution, and 4,096-module walks on a 256 KiB thread stack.

  • Body eligibility checks reuse immutable primitive-record layout facts and check each reached typed expression once per pass, including shared graphs. Answers remain local to that pass, so rewritten bodies and other lookup scopes are checked again. tests/body_eligibility.sh covers shared nodes, malformed backedges, record rewrites and distinct same-named declarations; the compiler type matrix checks concrete builtin value classification. bench/body_eligibility.py measures paired checking, C emission and bundle construction from source and saved IR, requiring unchanged output bytes and independent native/VM arithmetic results. It can include offline real package checks. This does not establish general Go/C performance parity.

  • Portable bundle writing omits native assembly templates while retaining the checked bodies and full native .zir data. It measures the payload and writes directly to files or pipes without a temporary payload file. tests/zx_portable_write.sh checks graph immutability, binary assets, certificates, persistent state, append streams and write failures; tests/bundle_libraries.sh covers shared and included code. bench/zx_metadata.py compares bundle size, packing and fresh-host loading with a preserved compiler, including a reader/writer crossover and ordinary bundles without assembly. Its large comment annotations are a stress case.

  • C translates assembly operand aliases to positional references, including aliases that are host keywords. Further direct Go architecture/instruction coverage and full platform parity remain open. Compiler output buffering also supports hosts without Unix memory streams and write-only callback streams; Windows builds use native directory creation and accept backslash input paths. tests/text_stream.sh covers empty and binary output, positions, write errors and temporary-file fallback. bench/android_execution.py prepares matched C/Go controls and checks device timings against an independent oracle; these single-workload results do not establish overall C/Go parity or Android compilation speed.

  • Go output optionally uses the shared GNU assembly emitter through cgo when built with -tags=ziran_asm and CGO_ENABLED=1. Ordinary builds retain the checked Go body behind a compile-time-disabled branch. Native function and local-block bridges preserve CPU guards, GNU constraints, labels and caller memory aliases. Flat record results cross as primitive fields; pointer-bearing objects and unsupported local pointer operands keep their checked bodies. tests/go_assembly.sh covers source/saved IR, package startup, concurrency, native test modules, output pruning and strict cgo pointer checking. bench/go_assembly.py measures whole-loop and per-operation placements: cgo transitions can dominate small operations, so native execution is opt-in. With CGO_ENABLED=0, the same -tags=ziran_asm opt-in now emits direct AMD64 Go ABI0 assembly for represented numeric functions and register-result blocks. GNU alternative columns select one complete representable operand column, retaining tied operands. Fixed registers, integer/float widths, flat result records, local labels and AT&T dialect alternatives retain their checked bindings. Generated Go declarations describe the argument/result layout; leaf instructions preserve the stack, frame and goroutine registers. CPU selection is cached from CPUID and checks OS-enabled extended register state before AVX variants. An available but unrepresented earlier variant retains the checked body instead of selecting a later variant out of order. Pointer results, pointer operands, memory-result blocks, stack-changing instructions, external calls/data and other unrepresented GNU forms keep the checked Go body in this path. Existing cgo builds retain their native bridge. On the tested Go 1.24 toolchain, long direct assembly loops can delay Go scheduling and garbage collection; the cgo path remains available. Native Go assembly uses package builds (go build -tags=ziran_asm .), where Go also compiles the generated .s companions. tests/go_direct_assembly.sh checks mixed ABI layouts, CPU predicates against the C compiler, native dispatch, unsupported variants, GC/stack stress and cross compilation.

  • Generic functions and local blocks retain assembly through concrete specialization, including saved-library imports. Each instance validates operands and its portable body. Caller-owned pointer/array types retain their identity, while fixed library types remain in the defining scope. tests/generic_assembly.sh checks C/Go assembly and forced fallback, VM fallback, flat records, multiple results and invalid instances.

  • JSON diagnostics carry a schema version, structured initializer, assignment, argument, and return type details, and related declaration locations where available.   • The native ziran command, including its launcher and package child-process transport, and zi-fmt are implemented in Ziran. Their build compiles .zi to native output without handwritten C command adapters or shell/AWK formatting policy. Package allocations use the language's size_of instead of C size helpers. tests/native_commands.sh rebuilds the command from its source and saved IR, retaining version output, tool discovery from PATH, inspection commands, checking, and formatting. tests/package_process.sh checks source and saved IR, literal arguments, child-only environment changes, working directories, exit/signal status, truncation with pipe draining, and rejected arguments. The formatter preserves strings, raw-string delimiter columns, and nested comments; it writes through a temporary file beside the source and retains permissions and symlinks. tests/formatter.sh checks semantic preservation, idempotence, filesystem errors, a saved-IR command rebuild, and scanner agreement on C, Go, and .zx. The parser, checker, native backends, and portable runtime still contain C; the compiler is not yet fully self-hosted.

  • Portable slices and arrays of imported records compare their element type identities across module aliases, retaining shared slice storage when callers and callees use different spellings for the same record. tests/portable_imported_record_slices.sh checks aliases, returned slices, shared mutation, empty views, array value copies, generic record elements, and rejection of distinct same-named records from source and saved IR.

  • Self-hosting moves the compiler core into Ziran one rule set at a time. Each cmd/compiler_*.zi module owns its rules; C calls the generated code through a thin boundary that keeps IR storage, spans and diagnostics, and the replaced C is deleted. Fresh builds first compile a bootstrap compiler from the seeds in bootstrap/, then rebuild every tool from the maintained .zi sources. A seed also keeps the generated headers of standard modules it uses, such as vec.h. make check-bootstrap verifies the seeds and make update-bootstrap regenerates them. Each tests/compiler_<module>.sh checks source and saved IR on C, Go and .zx, a deterministic input corpus, seed agreement and the C boundary.

Integer literals with _ separators, 0b binary and u64 values above the s64 maximum share one parser across the checker, constant folding, range lowering, proofs, the VM verifier, evaluator and global initializers, and the C and Go emitters; C header constants are written in decimal. tests/integer_literal_spellings.sh checks C, Go, native and portable results. Generated C drops the bounds check on an array, slice or string index it proves in range from integer types, literals, &, |, ^, %, /, >>, << by a constant, +, - and *, and from loop conditions. A local's range follows its initializer through any chain of locals, such as line := row * 16 and at := line + offset, and a declaration without a value starts at zero. An enclosing if or while condition, earlier && and || operands and an earlier if ending in return, break or continue bound what they compare until it changes. Their comparisons of sums and products, such as input.count < (height + 3) * stride + width + 4, prove indexes such as row * stride + column below a slice count or array length when no step of the guard or the index can wrap, so first + 1 + second bounds neither term; tests/guarded_index_ranges.sh checks four proven functions and ten reads that keep their checks. A local or parameter counts only when every write to it is a visible assignment and nothing takes its address. A counter is bounded by an enclosing while condition until the body writes it again; a write followed by continue, break, return or unreachable in its own block, such as the step a for loop runs before a continue, does not count for reads after that block. When several facts bound a counter, such as i <= 31 from a guard and i <= height - 1 from the loop, each is tried. A factor's sign and the final comparison may take away up to three facts, so stride >= width and width - 1 - j >= 0 show stride >= 1, and products of 32-bit values such as (cast(s64)height - 1) * stride keep their range when no corner overflows. A local declared from ifx is proven for each branch, a counter an index shrinks with is replaced by its lower bound, and a guard comparison with a narrow step that might wrap, such as cast(s64)(height - 1) in s32, counts where the other facts show it did not. The search keeps only facts linked to the index's own values, so extra guard comparisons never lose a proof, and a fact times a bounded value covers products such as radius * stride. Effect laws compare the derived class (#law Name effect Proc == pure; against pure, observing, mutating, or external), bounds laws compare a fixed-array bound (Type == N, >= N, <= N over compile-time values), and the size kind compares a type's laid-out byte size the same way; comparison payloads keep their procedures and type fields in linked bundles. Every checked procedure also carries a derived effect class — pure, observing, mutating, or external — computed from its body to a fixpoint and serialized in its .zir signature as ABI. #parallel for regions ride the range lowering into the checked while and the region checker accepts a body only when every called procedure is pure or observing, writes target iteration-local bindings, Vec mutations stay on region storage, regions do not nest, and the shape is a for; source and saved IR build byte-identical bundles everywhere. The native C99 target executes forward regions on pthreads through ziran_parallel.h: each region becomes a file-scope worker over contiguous index chunks that reaches captured fixed arrays through a pointer and other captures by value, the thread count is the processor count unless ZIRAN_PAR_THREADS chooses 1-64, and files containing workers compile with -pthread. Natively run bundles use the engine's worker pool. Reverse regions, the portable VM, and Go run serially with an emitted downgrade marker, as the backend-duties clause permits; region-leaving return/break/continue are rejected so no schedule can skip iterations. #parallel_gpu for regions validate before offload per the GPU clause: pointer storage, pointer-bearing call arguments, and allocator-backed Vec mutation are rejected, and external-class calls were already barred by the region rules. On the native C target on Linux and Android, cmd/zir/zir_emit_gpu.c lowers a region and its callees to an OpenGL ES 3.1 compute shader and include/ziran_gpu.h runs it on the fastest device it measures, loading EGL and GLES at run time. Regions of 32-bit integers, float32, bytes and booleans with capture[it] writes qualify; 64-bit values, nested for, globals, records, signed or variable division and foreign calls keep the CPU worker path with an emitted marker. A failed bounds check, a used up loop budget or a refused shader discards device results and reruns the region on the CPU. The ZX engine, the portable VM and Go do not offload. tests/gpu_offload.sh compares every device with the CPU.
  • ziran explain exposes a stable registry for every diagnostic code currently emitted by the compiler, with textual and JSON output. ziran explain --list enumerates the registry, and tests/explain.sh fails if a new emitted code is omitted. Native C and Go lowering reports malformed module state and output-file failures through registered target codes, including JSON lines for unwritable output destinations.
