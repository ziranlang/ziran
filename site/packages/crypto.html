sha256

Ordinary library procedures retain package-qualified native symbols. A consuming executable owns any explicit C ABI it chooses to export. SHA-256 and HMAC-SHA-256, extracted from Waozi’s Mesh implementation. Portable Ziran; no foreign cryptographic implementation.

Import with #import "crypto/sha256".

The buffered block. Each loader reads the block's 16 big-endian words where it lies; Sha256Rounds hashes them.

One 64-byte block from a slice, so portable bundles can hash too.

One 64-byte block read in place at BLOCK, for the pointer forms. Without a bounds check per byte, a package hashes as fast on phones, which build at -Oz, as it did with Mesh Client's own SHA-256.

crypto/src/kdf.zi

kdf

Key derivation functions: PBKDF2-HMAC-SHA-256 (with precomputed HMAC midstates, no silent salt truncation) and RFC 5869 HKDF-SHA-256. Portable Ziran; wipes intermediate secrets before returning.

Import with #import "crypto/kdf".

Pbkdf2Sha256 :: (password: []u8, salt: []u8, iterations: u64, output: []u8) -> bool

PBKDF2-HMAC-SHA-256 with arbitrary salt length (up to 1024 bytes) and arbitrary output length (up to 1024 bytes). Uses precomputed HMAC-SHA-256 ipad/opad midstates (~2x faster than recomputing the key block per round).

Pbkdf2Sha256Pointer :: (password: *u8, password_length: s64, salt: *u8, salt_length: s64, iterations: u64, output: *u8) -> s32

Pointer form of PBKDF2-HMAC-SHA-256 producing one 32-byte key. Supports salts up to 1024 bytes without silent truncation.

HkdfExtract :: (salt: []u8, ikm: []u8, prk: []u8) -> bool

RFC 5869 HKDF-Extract(salt, IKM) -> PRK (32 bytes). An empty salt uses 32 zero bytes as specified by RFC 5869 Section 2.2.

HkdfExpand :: (prk: []u8, info: []u8, okm: []u8) -> bool

RFC 5869 HKDF-Expand(PRK, info, L) -> OKM (up to 255 * 32 = 8160 bytes).

HkdfSha256 :: (salt: []u8, ikm: []u8, info: []u8, okm: []u8) -> bool

RFC 5869 one-shot HKDF-SHA-256(salt, IKM, info) -> OKM.
