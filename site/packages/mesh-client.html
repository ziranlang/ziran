Overview

Quick start

Import mesh_client/client and mesh_client/sync, then:

  • Set Client.app_id; supply a Device with a persisted Ed25519 key and signer, and a cryptographically random 64-digit hex nonce callback.
  • Implement the host boundaries SendRequest (bounded HTTP) and ReceiveEvent (bounded WebSocket); every response buffer must be NUL terminated, including on error. A native host can adapt both to Ziran's curl HTTP and WebSocket modules.
  • Persist Session to keep bearer tokens across restarts; account keys must outlive them.
  • Own in the app: payload format, response merge, key store, platform transport. The library does not provision keys, revoke devices, store account data, or merge application records.

Wire compatibility

Released protocol bytes keep their original spelling; renaming them would invalidate signatures or stop existing users from decrypting:

  • daochi-* signature contexts, X-Daochi-* HTTP headers;
  • daochi-record-v1 envelopes and daochi-entity-v1/* key derivation strings;
  • account-key-v1 and ksync-account-key-v2 key files, account IDs, stored state, and result codes.

Old daochi_client imports and Daochi* source aliases are not provided. Release APIs are MeshRelease, MeshParseRelease, MeshSha256Matches, and the MESH_RELEASE_* limits. The package rename does not migrate stored data.

Native links

  • record, crypto_native, entity_native, keys_native: link libsodium.
  • record_codec: native hosts link zlib (-lz); Emscripten hosts use -sUSE_ZLIB=1.
  • keys signing uses the oqs package.

Registration hint

Session.registration remembers one successful device registration for up to an hour between successful requests, scoped to the normalized node URL, account, app, client, device key ID, and public key; sync then sends only its signed transaction. The node still verifies both signatures and revocation on every request. A missing-device response permits one fresh registration and a newly signed transaction; revoked devices cannot register again. Clearing or renewing the bearer session clears the hint. Hosts may save this public metadata with WriteRegistration and restore it with ReadRegistration; it contains no private key or bearer token.

Async transport

BeginRequest/PollRequest and BeginSync/PollSync with AsyncTransport: the poll returns -1 while pending, 0 on transport failure, or 1 with the HTTP status when complete; every completed response must be NUL terminated. Keep the pending operation, session, client identity, signing contexts, body, and extra header strings alive until completion or cancellation; each pending operation has its own transport context. CancelRequest and CancelSync release an active transfer and finish with AUTH_REQUEST_FAILED. Both modes share the one-login retry after a 401; sync modes share the registration and transaction builders. A transport may resend a signed POST when a reused connection drops after the node committed it; sync recognizes the exact replay response and retries with a fresh nonce inside its bounded recovery budget. The node's replay protection remains enforced.

SyncFlow: accounts larger than one buffer

  • After a capacity failure, sync switches to the server's encrypted record pages: it signs each page request, retries interrupted transfers, and validates forward cursor progress. One bounded response buffer spans pages; total account size has no fixed client buffer limit. Smaller record pages are tried when a page overflows; other failures keep the existing result codes. An optional transport failure callback reports TRANSFER_FAILURE_CAPACITY.
  • Host callbacks load and save account-and-node-local SyncPageState, prepare the app's current encrypted records, and accept each response. accept must atomically merge records and persist the proposed next state; returning false does not advance durable progress. Only a terminal page may advance the account watermark. On restart the library resumes the saved cursor; cancel releases the current transfer and owned request memory. The clock callback refreshes transaction time between pages. These callbacks contain app storage policy, not page requests or transport retry decisions.
  • prepare receives the maximum encrypted record count for the next upload, including any reduction after an oversized page; retain its returned body until the next prepare call or completion.
  • Zero means download only: after overflow recovery or while resuming a partial download, uploads are omitted until the terminal page, so the download cursor cannot keep moving. A later sync uploads the retained local queue.

Signed request headers

sync.PrepareRequestHeader prepares the same account/device signed v6 transaction for an exact HTTP method, path, and byte-counted body, including empty GET/HEAD bodies and binary blob uploads. Hosts that already stream and hash the body can use sync.SignTransactionHeader with an explicit transaction.SyncTransaction; its account, app, and device must match the supplied client. PrepareSyncHeader retains the existing POST sync behavior. The host still owns transport, pinned-node policy, session/key storage, and remote acknowledgment handling.

Tests

Runs with the toolchain selected by ziran pkg path ziran; includes portable .zx URL and wire tests and a saved .zir to .zx round trip. Portability

URL policy, wire builders, and signed device registration message construction compile and run as portable .zx. The full HTTP client is not yet a .zx bundle: host transport, digest, and signer callbacks need bundle capabilities. Native Linux integration is tested; browser and Android transports are application host work. Strings use Ziran's TextView and bounded TextUntilNul instead of a native string-layout adapter.
