std/thread_windows

Background work for native 64-bit Windows programs. The caller owns one stable Thread record from Start until Finished or Wait reports completion. Results and notification arguments stay alive until then. Completion waits for the notification and C runtime cleanup, not just the procedure's return.

Stable Needs: Native Windows. Shipped in release v0.3.1.

The notification runs on this worker and must not join or restart it. _beginthreadex retains a waitable handle and releases C runtime thread storage when ThreadRun returns. The owner closes the handle after waiting.

ThreadRunning :: (thread: *Thread) -> bool
ThreadComplete :: (thread: *Thread, milliseconds: u32) -> bool
ThreadFinished :: (thread: *Thread) -> bool

A zero-time wait checks the actual native thread exit and never waits for its procedure, notification, or TLS cleanup. Successful polling consumes the handle once and makes the record reusable.
